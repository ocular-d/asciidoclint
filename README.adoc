= AsciiDocLint Workspace
:toc: preamble
:toclevels: 2
:experimental:

A comprehensive workspace for AsciiDoc linting, documentation quality assurance, and tooling built with TypeScript and pnpm workspaces.

== Overview

This repository contains multiple related packages that work together to provide comprehensive AsciiDoc linting capabilities:

* *@asciidoclint/core* - TypeScript-based AsciiDoc linting engine with configurable rules
* *@asciidoclint/cli* - Command-line interface for interactive linting
* *@asciidoclint/rules-standard* - Standard rule set for common documentation quality checks
* *examples/* - Integration test examples and usage demonstrations

== Quick Start

=== Prerequisites

* Node.js 18 or later
* pnpm 8 or later

=== Installation

[source,bash]
----
# Clone the repository
git clone https://github.com/ocld/asciidoclint.git
cd asciidoclint

# Install dependencies for all packages
pnpm install

# Build all packages
pnpm build
----

== Release Process

This project uses independent package versioning with automated validation:

=== Automated Release Workflow

The release system includes:

1. *Change Detection*: Analyzes commits for release-worthy changes using conventional commits
2. *Staging Release*: Publishes packages with `@next` tag for validation
3. *Comprehensive Validation*: Tests installation, functionality, integration, and performance
4. *Promotion to Stable*: Promotes to `@latest` tag after successful validation
5. *GitHub Release*: Creates tagged releases with automated changelog

=== Manual Release Process

[source,bash]
----
# 1. Create changeset describing your changes
pnpm changeset

# 2. Version packages based on changesets
pnpm changeset:version

# 3. Build and test before publishing
pnpm build
pnpm test

# 4. Publish to staging (automated via CI)
pnpm changeset:publish --tag next

# 5. Validation runs automatically via GitHub Actions
# 6. Packages promoted to stable after validation passes
----

=== Release Validation

The automated validation process includes:

* *Cross-Platform Testing*: Linux, macOS, Windows compatibility
* *Multi-Version Support*: Node.js 18, 20, 21 testing
* *Installation Verification*: Package installation and dependency resolution
* *Functionality Testing*: CLI commands and core API functionality
* *Integration Testing*: Real-world usage scenarios with example projects
* *Performance Benchmarking*: Execution time and memory usage validation
* *Security Scanning*: Dependency vulnerability detection

=== Secret Management

For maintainers setting up automated releases:

1. *NPM Registry Token*:
   - Create automation token at https://npmjs.com
   - Add to repository secrets as `NPM_TOKEN` 
   - Ensure token has publish permissions for `@asciidoclint/*` scope

2. *GitHub Permissions*:
   - Repository must have Actions enabled
   - Workflows require `contents: write`, `packages: write`, `pages: write` permissions
   - Secrets stored in repository Settings → Secrets and Variables → Actions

3. *Validation Environment*:
   - GitHub Actions provides automated cross-platform testing
   - Release validation triggers on staging package publication
   - Failed validations create GitHub issues with rollback procedures

== Configuration

=== CLI Configuration

Create `.asciidoclintrc.json` in your project root:

[source,json]
----
{
  "rules": {
    "title-case": "error",
    "no-trailing-spaces": "warning", 
    "max-line-length": {
      "severity": "warning",
      "maxLength": 120
    }
  }
}
----

=== Rule Configuration Options

* `"off"` - Disable the rule
* `"info"` - Informational messages only
* `"warning"` - Warning level (doesn't fail builds)
* `"error"` - Error level (fails builds with exit code 1)

=== Advanced Configuration

[source,json]
----
{
  "rules": {
    "title-case": "error",
    "no-trailing-spaces": "warning",
    "max-line-length": {
      "severity": "warning", 
      "maxLength": 100,
      "ignoreUrls": true,
      "ignoreCodeBlocks": true
    }
  },
  "ignorePatterns": [
    "generated/**/*.adoc",
    "vendor/**/*.adoc"
  ]
}
----

== Usage Examples

=== Basic Usage

[source,bash]
----
# Lint all AsciiDoc files in current directory
asciidoclint **/*.adoc

# Lint specific files
asciidoclint README.adoc docs/user-guide.adoc

# Use specific configuration file
asciidoclint docs/*.adoc --config custom-config.json
----

=== Output Formats

[source,bash]
----
# Stylish output (default)
asciidoclint docs/*.adoc

# JSON output for programmatic use
asciidoclint docs/*.adoc --format json

# Compact output for CI logs
asciidoclint docs/*.adoc --format compact
----

=== CI Integration

[source,bash]
----
# Fail build on errors, allow warnings
asciidoclint docs/**/*.adoc

# Fail build if more than 5 warnings
asciidoclint docs/**/*.adoc --max-warnings 5

# Quiet mode (errors only)
asciidoclint docs/**/*.adoc --quiet
----

== Architecture

=== Package Dependencies

The packages have the following relationships:

* `@asciidoclint/cli` depends on `@asciidoclint/core` and `@asciidoclint/rules-standard`
* `@asciidoclint/rules-standard` depends on `@asciidoclint/core`
* `@asciidoclint/core` is independent with only external dependencies
* Examples use `workspace:*` protocol for internal dependencies during development

=== Development Workflow

1. *Core Changes*: Modify `@asciidoclint/core` for engine improvements
2. *Rule Development*: Add rules to `@asciidoclint/rules-standard`
3. *CLI Features*: Extend `@asciidoclint/cli` for user interface improvements
4. *Integration Testing*: Update example projects to test new features
5. *Documentation*: Update README and example documentation

== Troubleshooting

=== Common Issues

*Package not found after installation*::
Verify NPM registry permissions and package publication status.

*CLI command not available*::
Ensure CLI package is installed globally or use `npx asciidoclint`.

*Configuration not loading*::
Check configuration file syntax and placement in project root.

*Rules not working*::
Verify rule names match exported rules from `@asciidoclint/rules-standard`.

*Build failures in CI*::
Check Node.js version compatibility and dependency installation.

=== Development Issues

*TypeScript errors in packages*::
Run `pnpm type-check` to identify type issues across packages.

*Test failures*::
Use `pnpm test` to run all tests or target specific packages.

*Linting errors*::
Run `pnpm lint` to identify and fix code style issues.

*Workspace dependency issues*::
Use `pnpm install` to refresh workspace links and dependencies.
