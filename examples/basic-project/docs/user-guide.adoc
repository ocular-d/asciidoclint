= User Guide for Basic Project
:toc:
:toclevels: 3

This document demonstrates basic AsciiDoc linting with various common issues.

== Getting Started

Welcome to the basic project user guide. This section covers the fundamental concepts.

=== Installation

To install the basic project:

[source,bash]
----
npm install basic-project
----

=== Configuration

The configuration file should be placed in the root directory.

== Features

The basic project includes the following features:

* Simple linting rules
* Configuration management
* CLI integration

=== Rule Configuration

Rules can be configured in the `.adoc-lintrc.json` file:

[source,json]
----
{
  "rules": {
    "title-case": "error",
    "no-trailing-spaces": "warning",
    "heading-spacing": ["warning", {
      "requireBefore": true,
      "requireAfter": true,
      "exceptions": []
    }]
  }
}
----

== Usage Examples

This section provides practical examples of using the linter.

=== Basic Usage

Run the linter on your AsciiDoc files:

[source,bash]
----
asciidoclint docs/*.adoc
----

=== Advanced Usage

For more detailed output:

[source,bash]
----
asciidoclint docs/*.adoc --format stylish
----

== Troubleshooting

Common issues and their solutions:

. *Permission denied*: Check file permissions
. *Config not found*: Ensure `.adoc-lintrc.json` exists
. *Rule errors*: Verify rule configuration syntax

== Conclusion

This guide covers the basic usage of the AsciiDoc linter. For more advanced topics, see the advanced examples.

== Inline Directive Usage

AsciiDocLint supports inline directives to disable or enable specific rules within your documents. This is useful when you need to temporarily ignore certain rules for specific content.

=== Basic Directive Syntax

Use `// adoc-lint` comments to control rule enforcement:

[source,asciidoc]
----
// adoc-lint disable max-line-length
This line can be as long as you need it to be without triggering the max-line-length rule.
// adoc-lint enable max-line-length
----

=== Heading Spacing Examples

The `heading-spacing` rule requires blank lines around headings (except level 1):

[source,asciidoc]
----
= Document Title

Content here.

== Proper Heading

This heading has proper spacing.

=== Another Section

Also properly spaced.
----

==== Common Violations

Here are examples of heading spacing violations:

// adoc-lint disable heading-spacing
==== Bad Example One
No blank line before or after.
==== Bad Example Two
Consecutive headings without spacing.
// adoc-lint enable heading-spacing

=== Supported Directives

* `// adoc-lint disable <rule>` - Disable a specific rule from this point forward
* `// adoc-lint enable <rule>` - Re-enable a specific rule from this point forward  
* `// adoc-lint disable-all` - Disable all rules from this point forward
* `// adoc-lint enable-all` - Re-enable all rules from this point forward

Supported rules include:

* `max-line-length` - Controls line length limits
* `no-trailing-spaces` - Controls trailing whitespace detection
* `title-case` - Controls title case formatting
* `heading-spacing` - Controls blank line requirements around headings

=== Multiple Rules

You can specify multiple rules in a single directive using comma separation:

[source,asciidoc]
----
// adoc-lint disable max-line-length, no-trailing-spaces
This content can have long lines and trailing spaces without warnings.
// adoc-lint enable max-line-length, no-trailing-spaces
----

=== Priority Rules

When using nested directives, specific rule controls take priority over `disable-all` and `enable-all`:

[source,asciidoc]
----
// adoc-lint disable-all
// adoc-lint enable max-line-length
This line will still be checked for length despite disable-all.
----

=== Configuration

Inline directives are enabled by default. You can disable them globally in your configuration:

[source,json]
----
{
  "rules": {
    "title-case": "error",
    "heading-spacing": "warning"
  },
  "enableInlineDirectives": false
}
----

Or via the CLI:

[source,bash]
----
asciidoclint docs/*.adoc --disable-inline-directives
----
