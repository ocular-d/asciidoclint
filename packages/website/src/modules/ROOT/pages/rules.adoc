= Rules
:page-aliases: linting-rules

AsciiDocLint includes four standard rules that help maintain consistent, high-quality AsciiDoc content.
Each rule can be configured with different severity levels (`error`, `warning`, `info`, or `off`) to match your project's needs.

== Available Rules

* **heading-spacing**: Requires blank lines around headings (except level 1) for better document structure. Supports ignoring AsciiDoc attribute lines before headings
* **title-case**: Enforces proper title case formatting for document and section titles
* **max-line-length**: Limits line length to improve readability and code review experience
* **no-trailing-spaces**: Removes trailing whitespace that can cause formatting issues

== Rule Details

=== heading-spacing

Requires blank lines around headings (except level 1 document titles) to improve document structure and readability.

==== Description

The heading-spacing rule enforces consistent spacing around headings to create better visual separation and improve document readability. By default, the rule requires:

* A blank line before each heading (except level 1 document titles)
* A blank line after each heading (except level 1 document titles)
* Level 1 headings (`= Document Title`) are exempt from spacing requirements

==== Configuration Options

* `requireBefore`: Require blank line before headings (default: `true`)
* `requireAfter`: Require blank line after headings (default: `true`)
* `exceptions`: Array of heading levels to skip checking (default: `[]`)
* `allowConsecutiveHeadings`: Allow headings without spacing when they appear consecutively (default: `false`)
* `ignoreAttributeBlocks`: Ignore simple attribute lines before headings like `[#anchor]` and `[.role]` (default: `false`)
* `ignoreComplexAttributes`: Ignore complex attribute patterns like `[#id.role1.role2]` and block shortcuts (default: `false`)
* `maxAttributeDepthScan`: Maximum number of consecutive attribute lines to scan backwards (default: `10`)

.Basic configuration
[source,json]
----
{
  "rules": {
    "heading-spacing": "warning"
  }
}
----

.Advanced configuration
[source,json]
----
{
  "rules": {
    "heading-spacing": ["error", {
      "requireBefore": true,
      "requireAfter": true,
      "exceptions": [3],
      "allowConsecutiveHeadings": false
    }]
  }
}
----

.Attribute handling configuration
[source,json]
----
{
  "rules": {
    "heading-spacing": ["warning", {
      "requireBefore": true,
      "requireAfter": true,
      "ignoreAttributeBlocks": true,
      "ignoreComplexAttributes": true
    }]
  }
}
----

==== Examples

.Before (violates rule)
[source,asciidoc]
----
= Document Title
Content directly after title.
== Section One
Content without spacing before heading.
=== Subsection
No spacing around this heading either.
== Section Two
Final content.
----

.After (correct)
[source,asciidoc]
----
= Document Title

Content after title.

== Section One

Content with proper spacing.

=== Subsection

Proper spacing around this heading.

== Section Two

Final content.
----

.Attribute handling (with ignoreAttributeBlocks: true)
[source,asciidoc]
----
= Document Title

Content here.
[#anchor-id]
== Section With Anchor

[.role-class]
== Section With Role

[source,javascript]
[#code-example]
[.highlighted]
=== Multiple Attributes

Regular content.
== Section Without Attributes (still requires spacing)

Final content.
----

==== Performance Notes

The heading-spacing rule uses caching to optimize performance when processing large documents with many headings. It executes before other rules like `max-line-length` to ensure optimal rule interaction.

==== Attribute Handling

The heading-spacing rule includes advanced support for ignoring AsciiDoc attribute lines that appear immediately before headings. This feature prevents false violations when using common AsciiDoc patterns:

.Supported attribute patterns:
* **Simple anchors**: `[#anchor-id]`
* **Role attributes**: `[.role-name]`
* **Block shortcuts**: `[source,javascript]`, `[NOTE]`, `[TIP]`, `[WARNING]`
* **Language shortcuts**: `[,python]`, `[,javascript]`
* **Complex combinations**: `[#id.role1.role2]`, `[.role1#id.role2]`
* **Named attributes**: `[key=value]`, `[title="Section Title"]`

When `ignoreAttributeBlocks` is enabled, the rule treats attribute lines as "transparent" for spacing purposes, checking spacing requirements before the entire attribute block rather than immediately before the heading.

The rule also includes block context awareness to prevent false positives from bracket syntax inside code blocks or literal text.

==== Rule Interactions

* **max-line-length**: The `max-line-length` rule ignores blank lines to prevent conflicts when `heading-spacing` adds spacing
* **Execution Order**: `heading-spacing` runs first to allow other rules to process the properly spaced document

**Note**: When attribute handling is enabled, the rule will generate additional warnings for malformed attribute syntax to help identify potential formatting issues.

=== title-case

Ensures document and section titles follow proper title case formatting with consistent capitalization rules.

==== Description

The title-case rule enforces these formatting standards:

* First and last words are always capitalized
* Articles, conjunctions, and short prepositions are lowercase (unless first/last word)
* Lowercase words: 'a', 'an', 'and', 'as', 'at', 'but', 'by', 'for', 'in', 'nor', 'of', 'on', 'or', 'so', 'the', 'to', 'up', 'yet'

==== Examples

.Before (violates rule)
[source,asciidoc]
----
= user guide for basic project
== getting started
== improper title case  
== Best practices
----

.After (correct)
[source,asciidoc]
----
= User Guide for Basic Project
== Getting Started
== Improper Title Case
== Best Practices
----

=== max-line-length

Enforces a maximum line length to improve readability and maintainability of AsciiDoc documents.

==== Description

The max-line-length rule checks that lines do not exceed the configured maximum length.
The default limit is 120 characters, but this can be customized per project needs. 

**Note**: Blank lines are automatically ignored by this rule to prevent conflicts with the `heading-spacing` rule.

==== Configuration Options

* `maxLength`: Maximum allowed line length (default: 120 characters)

.Custom line length configuration
[source,json]
----
{
  "rules": {
    "max-line-length": ["warning", { "maxLength": 100 }]
  }
}
----

==== Examples

.Before (violates rule)
[source,asciidoc]
----
This line is intentionally very long and would normally trigger the max-line-length rule, but it's disabled for this section so no warning should be generated.

AsciiDocLint supports inline directives to disable or enable specific rules within your documents. This is useful when you need to temporarily ignore certain rules for specific content that requires longer lines.
----

.After (correct)
[source,asciidoc]
----
This line is intentionally very long and would normally trigger the max-line-length rule, 
but it's disabled for this section so no warning should be generated.

AsciiDocLint supports inline directives to disable or enable specific rules within your documents. 
This is useful when you need to temporarily ignore certain rules for specific content that 
requires longer lines.
----

=== no-trailing-spaces

Removes trailing whitespace at the end of lines that can cause formatting inconsistencies.

==== Description

The no-trailing-spaces rule detects and reports any trailing spaces or tabs at the end of lines.
Trailing whitespace can cause unexpected formatting behavior and should be removed.

==== Examples

.Before (violates rule)
[source,asciidoc]
----
This section allows both long lines and trailing spaces without warnings.   
Another line with trailing spaces that should be ignored.    
This line has trailing spaces and should trigger a warning.   
----

.After (correct)
[source,asciidoc]
----
This section allows both long lines and trailing spaces without warnings.
Another line with trailing spaces that should be ignored.
This line has trailing spaces and should trigger a warning.
----

== Configuration by Use Case

Different types of documentation have different quality requirements.
Here are recommended configurations for common use cases.

=== API Documentation

API documentation requires the highest level of consistency and professionalism.
All rules should be strictly enforced.

.api.json
[source,json]
----
{
  "rules": {
    "title-case": "error",
    "no-trailing-spaces": "error", 
    "max-line-length": "warning"
  },
  "enableInlineDirectives": true
}
----

**Rationale:** API docs are often the first impression developers have of your project.
Strict formatting ensures professionalism and consistency across all technical documentation.

.Example usage
[source,bash]
----
$ adoc-lint docs/api/ --config configs/api.json
----

=== User Guides  

User guides balance quality with flexibility, allowing some formatting variation while maintaining readability.

.guides.json
[source,json]
----
{
  "rules": {
    "title-case": "warning",
    "no-trailing-spaces": "warning",
    "max-line-length": "info"
  },
  "enableInlineDirectives": true
}
----

**Rationale:** User guides prioritize content clarity over strict formatting.
Line length is informational only since explanatory content may legitimately need longer lines.

.Example usage
[source,bash]
----
$ adoc-lint docs/guides/ --config configs/guides.json
----

=== Tutorials

Tutorials focus on learning outcomes and may include informal language or long command examples.
Configuration is most relaxed here.

.tutorials.json
[source,json]
----
{
  "rules": {
    "title-case": "info",
    "no-trailing-spaces": "warning", 
    "max-line-length": "off"
  },
  "enableInlineDirectives": true
}
----

**Rationale:** Tutorial content often includes step-by-step instructions, command examples, and conversational language.
Only trailing spaces are enforced as warnings since they can cause copy-paste issues.

.Example usage
[source,bash]
----
$ adoc-lint docs/tutorials/ --config configs/tutorials.json
----

== Inline Directives

AsciiDocLint supports inline directives that let you control rules within your documents using special comments.
This is useful for handling exceptional content that doesn't fit standard formatting rules.

=== Basic Usage

==== Disable/Enable Single Rules

.Disable a specific rule temporarily
[source,asciidoc]
----
// adoc-lint disable max-line-length
This line is intentionally very long and would normally trigger the max-line-length rule, but it's disabled for this section so no warning should be generated.
// adoc-lint enable max-line-length
----

==== Disable/Enable Multiple Rules

.Disable multiple rules at once
[source,asciidoc]
----
// adoc-lint disable max-line-length, no-trailing-spaces
This section allows both long lines and trailing spaces without warnings.   
Another line with trailing spaces that should be ignored.    
// adoc-lint enable max-line-length, no-trailing-spaces
----

=== Advanced Patterns

==== Disable/Enable All Rules

.Disable all rules for legacy content
[source,asciidoc]
----
// adoc-lint disable-all
== improper title case
This section violates multiple rules: long lines, trailing spaces   , and improper title case.
But no warnings should be generated because all rules are disabled.
// adoc-lint enable-all
----

==== Nested Directives

.Complex directive combinations
[source,asciidoc]
----
// adoc-lint disable-all
// adoc-lint enable max-line-length
This line will still be checked for length despite disable-all.
Has trailing spaces but no warning since that rule is still disabled.   
// adoc-lint enable-all
----

=== Real-World Scenarios

==== Long Command Examples

.Disabling line length for code blocks
[source,asciidoc]
----
// adoc-lint disable max-line-length
[source,bash]
----
curl -X POST "https://api.example.com/v1/very-long-endpoint-name" -H "Authorization: Bearer very-long-token-that-exceeds-line-limit" -d '{"data": "value"}'
----
// adoc-lint enable max-line-length
----

==== External Content Integration

.Handling third-party content
[source,asciidoc]
----
The following section is imported from external documentation:

// adoc-lint disable title-case, no-trailing-spaces
== third party integration guide
This content comes from a third-party source and may not follow our style guide.   
We preserve it as-is to maintain accuracy.
// adoc-lint enable title-case, no-trailing-spaces
----
